# بوت Talkin Chat — Railway Music + Gifts

## متغيرات Railway المطلوبة
أضف هذه القيم من صفحة الخدمة في Railway عبر **Variables**، ثم نفّذ Redeploy:

```text
BOT_ID=اسم البوت
BOT_PWD=كلمة السر
BOT_MASTER=اسم الماستر
GROUP_TO_JOIN=أول غرفة يدخلها البوت
```

يدعم الإصدار الحالي أيضًا الأسماء القديمة `BOT_USERNAME` و`BOT_PASSWORD` و`FIRST_ROOM`،
لكن يُفضّل استخدام الأسماء الأربعة أعلاه. لا تضع كلمات السر داخل Git أو داخل Dockerfile.

لا تضع روابط الأغاني أو الهدايا. البوت يستخدم Railway Public Domain تلقائياً.

## التخزين الدائم للغرف والمستخدمين

يحفظ البوت الغرف التي دخلها في `tracked_rooms.json`، ويحفظ المستخدمين الذين
يجلبهم من كل غرفة في `room_users.json`. عند دخول الغرفة أو استعادة الاتصال،
يطلب البوت قائمة المستخدمين ويضيفها إلى الملف دون حذف المستخدمين السابقين.
وعند تنفيذ الأمر `inv`، يجمع البوت المستخدمين من هذه الملفات أولاً، ثم يدمج
أي مستخدمين جدد من المصدر المباشر أو قاعدة البيانات قبل تنفيذ الدعوات.

يبقى التوثيق في `verified_users.json`، وتبقى عضويات VIP في `vip_users.json`.
لا تحذف هذه الملفات عند استبدال نسخة البوت أو إعادة النشر. استخدم تخزينًا
دائمًا للمجلد في بيئة الاستضافة إذا كانت المنصة لا تضمن بقاء ملفات الحاوية.

أرصدة نقاط المستخدمين وجوائز الألعاب تُحفظ مركزيًا في `points.json`، بينما
إحصاءات عدد مرات اللعب والنقاط والرهانات لكل لعبة تُحفظ في `game_stats.json`.
لذلك لا تعتمد النقاط أو نتائج الألعاب على ذاكرة التشغيل، وتبقى متاحة بعد
تحديث ملفات البوت أو إعادة تشغيله ما دامت ملفات البيانات محفوظة.
